## 2. 예측 타겟

> 현재 `batch_purchases`는 구매 이벤트만 포함 (방문 로그 없음)  
> → 타겟 = **(구역 × 시간대) 셀별 일간 구매 이벤트 수**

marginalize로 두 KPI를 동시 산출:
- **구역별 구매량** = 시간대 차원 합산
- **시간대별 구매량** = 구역 차원 합산

방문 로그가 추가되면 `dataset.py`의 타겟 컬럼을 `구매수/방문수`로 교체하여 **구매전환율** 예측으로 확장 가능.

## 3. 모델 아키텍처

**PurchaseGridTransformer** (`model.py`)

```
입력: [B, L=7, N=84, F=8]
       └─ L: window_size (일)
       └─ N: 7 zones × 12 hours = 84 tokens
       └─ F: 구매수, 체류시간, 가격, 고객수, 고객군 비중×4

임베딩:
  zone embedding     [7,  d=96]  ─┐
  hour embedding     [12, d=96]  ─┤ 합산 → token embedding
  day-of-week emb    [7,  d=96]  ─┤ 요일 주기 학습
  positional emb     [L,  d=96]  ─┘ 일차 내 위치

Encoder: SpaceTimeBlock × 3
  ① Spatial attention  (B*L, N, d) → 구역×시간대 공간 관계 학습
  ② Temporal attention (B*N, L, d) → 7일간 시계열 패턴 학습
  ③ FFN (d → 4d → d)

Head: LayerNorm → Linear(d, horizon=1)
출력: [B, H=1, N=84]  (log1p 공간)
```

**파라미터 수:**
- d_model=96, n_heads=4, n_layers=3, dropout=0.1

## 4. 학습 설정 (`config.yaml`)

| 항목 | 값 | 비고 |
|---|---|---|
| window_size | 7일 | 입력 시퀀스 길이 |
| horizon | 1일 | 예측 스텝 |
| batch_size | 32 | — |
| optimizer | AdamW | weight_decay=0.01 |
| lr | 0.001 | warmup 5 epoch 후 cosine decay |
| loss | SmoothL1 (β=0.5) | 이상치 robust |
| grad_clip | 1.0 | — |
| max_epochs | 200 | early stopping patience=30 |
| 실제 종료 epoch | **16** | early stopping 발동 (epoch 46) |

**전처리**
- 입력 피처: 활성 셀(구매수>0) 기준 mean/std 정규화. count 피처(구매수, 고객수)는 log1p 후 정규화.
- 타겟: `log1p(구매 이벤트 수)`. 평가 시 `expm1`으로 역변환.
- 정규화 통계는 train에서 fit → val/test에 동일 적용.

## 8. 향후 개선 방향

1. **방문 로그 추가** → 현재 구매수 예측에서 **구매전환율** 예측으로 전환
2. **Multi-step horizon** → 1일 예측에서 7일 예측으로 확장 (`horizon: 7`)
3. **실제 데이터 교체** → dummy 대신 실제 시뮬레이터 출력 데이터 적용 시 MAPE 추이 재검증
4. **외부 피처 추가** → 공휴일, 이벤트 여부 등 외생 변수 (요일 임베딩이 이미 기반 확보)
